# 摄像头条码录入

## 使用

1. 商品页编辑或新增商品，留空条码即可在保存时自动生成唯一的 MP 内部条码；也可输入包装条码或点击「扫码绑定」。编辑商品可查看和下载 Code 128 条形码。
2. 开单页搜索栏旁点击「扫码」即自动启动后置摄像头，首次使用需允许浏览器摄像头权限。暂停或启动失败后可点击「开启摄像头」重试。
3. 每次识别匹配的在售商品加入本单 1 件。同一条码持续可见时只加入一次，移开约 1 秒后再扫可继续累加。也可手动输入条码确认。
4. 成功加购后，相机画面显示磨砂遮罩与打勾动画 0.5 秒，期间暂停接收新条码，随后自动恢复。选品完成后关闭扫码窗口，继续原有挂单或收款流程。

每个条码只绑定一个商品，保留前导零；校验正确的 UPC-A 与前补 0 的 EAN-13 按同一条码匹配。重复绑定、未知条码、停售商品都有提示。相机画面在浏览器本地识别，不上传视频。

## 环境与限制

- 手机和平板通过 HTTPS 站点访问；普通 HTTP 局域网地址不能使用摄像头。可用 Safari 或 Chrome 打开站点。
- 使用后置摄像头为默认偏好，授权后可从设备列表切换镜头。
- 暂停、关闭窗口、切换页面、浏览器进入后台时释放摄像头；回到页面后需主动重新开启。
- 若拒绝授权或摄像头被其他应用占用，可使用手动输入或修复权限后重试。
- 预览模式下的绑定只影响演示会话，刷新后重置；正式账户沿用现有云端保存机制。
- 新版本加载旧数据时自动补齐缺失条码并保存，已有条码不覆盖；预览种子数据同样自动补齐。暂不支持套餐条码及批量导入独立 barcode 字段。

## 验证

运行 `node tests/barcode.mjs` 检查匹配、唯一性、前导零、UPC/EAN 兼容、防重复与摄像头生命周期。

已在浏览器验证 Code 128 测试图解码、模拟视频流连续识别、移开后重新识别、暂停释放视频轨道，并验证手机布局与手动录入全流程。实际 iPhone/iPad 后置摄像头、标签反光和对焦效果仍需真机验收。

## 依赖

本地按需加载 `@zxing/browser` 0.1.5 的 UMD 包；包含 ZXing 解码逻辑，无运行时 CDN 请求。许可证见 `assets/vendor/zxing-browser-LICENSE.txt` 与 `assets/vendor/zxing-library-LICENSE.txt`。

条形码生成使用本地按需加载的 JsBarcode 3.12.1 Code 128 包，许可证见 `assets/vendor/jsbarcode-LICENSE.txt`。MP 条码为店内管理用途，不是申请的零售商品 EAN 编码。
